I'm building AKOMAYLESSONPLANNA, a digital marketplace where Filipino K-12 teachers can buy and sell educational resources (lesson plans, worksheets, presentations, etc.).

## CONTEXT FROM PREVIOUS PLANNING SESSIONS

I've completed extensive planning and finalized Features 01, 02, 02.5, 03, and 04. Here's what's been established:

### Project Overview
- **Name:** AKOMAYLESSONPLANNA
- **Type:** Two-sided marketplace (sellers: teachers, buyers: teachers)
- **Tech Stack:** Next.js 16, TypeScript, Tailwind CSS, Supabase, shadcn/ui

### CRITICAL PROCESS DECISION

We decided: **Finalize ALL features before creating database schema**

**Reasoning:** Features determine database structure. If we create the database first, then discuss features and realize we need different tables or columns, we'd have to redo the database work.

**Our Workflow:**

## REVIEWS & RATINGS CONTEXT

**Why This Matters:**
- Reviews are the #1 factor in purchase decisions (surveys show 90%+ read reviews)
- Reviews build trust in new marketplace (no reviews = suspicious)
- Reviews help sellers improve their products
- Reviews create community engagement
- Reviews improve SEO (user-generated content)

**Current Database Schema (reviews table):**
```sql
id (UUID, PK)
product_id (UUID, FK → products)
buyer_id (UUID, FK → users)
rating (INTEGER, 1-5)
comment (TEXT)
verified_purchase (BOOLEAN)
seller_response (TEXT)
created_at (TIMESTAMP)
updated_at (TIMESTAMP)
```
