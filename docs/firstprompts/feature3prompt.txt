I'm building AKOMAYLESSONPLANNA, a digital marketplace where Filipino K-12 teachers can buy and sell educational resources (lesson plans, worksheets, presentations, etc.).

## CONTEXT FROM PREVIOUS PLANNING SESSIONS

I've completed extensive planning and finalized Feature 01 and Feature 02. Here's what's been established:

### Project Overview
- **Name:** AKOMAYLESSONPLANNA
- **Type:** Two-sided marketplace (sellers: teachers, buyers: teachers)
- **Tech Stack:** Next.js 16, TypeScript, Tailwind CSS, Supabase, shadcn/ui
- **Commission Model:** 20% platform commission (15% for Pioneer tier)
- **Payment Methods:** GCash, Maya (Philippines e-wallets)
- **Timeline:** 8-10 months (part-time: 20-30 hours/week)
- **Current Status:** shadcn/ui template already set up

### Feature 01 (Authentication & User Management) - COMPLETED ✅

**Key Outcomes:**
- Email/password auth + Google + Facebook OAuth
- No email verification upfront (only for sellers before uploading)
- Single role system: buyers can become sellers (keep buyer abilities)
- PRC ID verification only (manual admin approval, 3-year validity, 1-month grace period)
- 90-day "remember me" sessions
- No 2FA initially, 5 failed attempts = 30min lockout
- CAPTCHA on signup only
- Rich optional profiles (avatar, bio, subjects, grades, location, social links)
- Enhanced profiles for Pro/Pioneer tier

**Documentation:**
- Full decisions: `docs/brainstorming/2-feature-01-authentication-user-management.md`

### Feature 02 (User Profiles & Profile Management) - COMPLETED ✅

- Comprehensive storefront layout (stats, badges, products, reviews)

- Badge system: Verified (all sellers) + Pro/Pioneer + achievements
- Profile completion calculator with incentives
- Follow system, contact seller, share functionality

### CRITICAL PROCESS DECISION

We decided: **Finalize ALL features before creating database schema**

**Reasoning:** Features determine database structure. If we create the database first, then discuss features and realize we need different tables or columns, we'd have to redo the database work.

**Our Workflow:**
1. Discuss each feature in detail (all ~45 features)
2. Update the design document based on each discussion
3. After ALL features finalized, THEN create comprehensive database schema
